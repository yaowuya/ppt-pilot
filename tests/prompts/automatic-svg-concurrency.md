# 自动 SVG 并发验收

这是合成测试提示，不是已执行的跨宿主证据。只读规划诊断不得描述成真实模型并发或 PPT 生成验收。

## 提示

> 使用 ppt-start 继续一个已通过文稿、主题和锚点门禁的运行，生成剩余 40 页 SVG。不要询问我并发量；目标至少 5，根据宿主容量和生成结果自动提高，最多 10。每页仍须隔离生成，严格完成 QA、顺序提交和可恢复状态。

使用真实完整运行副本进行宿主验收，不得仅凭此提示补造批准。为避免遗漏限制，分别覆盖以下场景：

选 40 页是为了留出真实 10 路的观测窗口：正常批次 inventory 依次为 5、7、9、10、9。仅有 30 页时依次为 5、7、9、9，即使目标已经升到 10，也不能据此宣称实际出现过 10 路并发。

| 场景 | 必须观察的行为 |
|---|---|
| 宿主实际分配 10 个 generator 槽位 | 从目标 5 起，稳定验证结果累计 5／10／15 个后目标为 7／9／10；每批 width 创建后不变，新批采用新目标；无用户并发选择问题。 |
| 主任务及其他工作扣除后只剩 3 个 generator 槽位 | 目标至少 5，但实际最多 3，明确报告限制，不修改宿主配置。 |
| 活动批次 10 页、已有 3 个任务占用、可分配总容量 3 | 不追加；同 epoch 重复恢复与新 epoch 都不重复派发。一个归因任务完成后仅补 1 页。 |
| 宿主已知容量 0／未知容量／缺 durable lookup | 分别为 WAIT／保守 1／安全 width 1；缺 fresh isolation 必须阻断，不用当前上下文或嵌套 CLI。 |
| 收到限流、超时或失败 | 目标回到 5；不绕过原失败处理、退避及 blocker 自动重试，保留在途任务和 previous final。 |
| 有 pending interaction／文稿审查 pending／源稿文件变化 | 不因并发规划器 READY 跳过工作流；依原恢复优先级和源稿 gate 停止。 |
| 旧 width 3／4 活动批次与 v1 迁移 | 保留既有 inventory 与确定性迁移字节；不为升并发改写活动批次。 |
| 仅剩 2 页 | 只运行 2 页并说明尾批，不重复生成其他页凑数。 |

## 证据

真实宿主验收分别记录 Claude Code、Codex、DeepSeek Harness 的版本、已部署 Skill 摘要、运行目录、实际容量来源、task／attribution IDs、各时点在途数量与 completion、只读规划输入输出、顺序提交及 QA 证据。未执行的宿主保持 `PENDING`。

只读技能诊断可让独立 agent 对以上场景给出动作序列与停止条件，不进行真实生成；该结果仅标为 `EVIDENCE_CLASS: DIAGNOSTIC`。本地自动测试为 `static package + runtime planner`，均不能证明真实宿主允许 10 路或达到固定倍数加速。
