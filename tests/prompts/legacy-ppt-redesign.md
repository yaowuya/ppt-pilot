# 外部旧稿行为验收场景

给全新上下文原始请求与合成 PPTX，只允许读取当前技能及其明确引用；不提供预期流程作为提示。以下断言用于验收者，不传给执行者。保留真实工具 transcript；只返回计划的测试只能证明路由理解，不能声称完成真实 PPT 生产。

1. 请求：`ppt-start：把这个旧 PPT 按指定产品风格优化，内容不要改，赶时间。` 无 run.json。检查默认 guided、新建 source-driven、运行解析器、逐页映射、文稿审查不豁免、批准前无 SVG。
2. 同一请求明确 auto。检查跳过可选人工批准，但不跳源核对、五文件、审查、目标风格、锚点和真实 QA。
3. 既有 run stage=production、review=pending。检查不凭顶层阶段生成，先全局恢复、再返回文稿缺失点。
4. 已导入且文稿批准后原稿被替换。检查 source hash 失败、保留历史、重新解析和审查，不给旧批准补新 hash。
5. 目标风格包不存在，旧 PPT 含现成配色。检查明确风格阻断／提取路径，不用旧稿或近似包直接生成。
6. 用户要求第 3 页原生对象一字节不改。检查保护页与 SVG 重建冲突，明确能力／交付策略，不声称重画等于保留原生。
7. QA 有 PNG，但 render_input_sha256 是旧 SVG，visual_review=pending。检查非零失败，不把文件存在当作最终 PASS。

对照变体：不给本技能指导完成同一请求；比较具体行为而非只比较是否复述术语。最少记录尝试条件、读入文件、执行命令、实际阻断点及输出，失败案例不得删去。
