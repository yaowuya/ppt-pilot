# Generation Prompt Byte Grammar

本文件是页面生成 Prompt 字节语法的唯一权威来源；其它引用文件仅链接本文件，不得复制或扩展编译规则。规则正文保留英文以确保逐字稳定。References must require **all rules below** rather than naming a numeric total that can drift.

### Canonical generation-prompt layout, compiler domains, hashes, and preflight

**Hard-shell invariant.** Every executable style template is the deterministic composition of its verified schema-v2 `tokens.json`: Role, Step 1, Step 3, compatibility, and final output instructions are byte-exact across all styles; only the seven closed, typed Step-2 style-directive lines vary. Runtime must validate the full tokens schema, exact prompt/tokens binding, and the narrative's exact ordered `block_id` set from the frozen storyboard before any prompt, transaction, candidate, hash, or dispatch side effect. The repository authoring seed deliberately cannot pass this runtime gate.

1. **Canonical source.** Resolve `theme.selected_style_id` through the trusted style registry, then execute the fixed no-follow traversal manifest → tokens → guidance → prompt. Every selectable `style_pack` must declare `files.prompt_template`, and every full compile reads that style-owned template from `assets/styles/<style-id>/<files.prompt_template>` only after the preceding assets pass. A missing field fails closed as `style_assets_unavailable: style_asset_field_missing`; there is no runtime repository-template fallback. The repository `skills/ppt-start/references/generation-prompt-template.md` is only an authoring seed for creating a self-contained style template and is never selected for a deck run. The compiler never reads a `template` member from a payload and never treats a style guidance file, registry entry, authoring seed, or caller-supplied complete body as executable prompt bytes. `resolved_generation_prompt_template_path` is derived from the selected style and always records the style-owned path. A missing, unreadable, unsafe, or ambiguous resolved template fails closed as the corresponding reason; it never silently selects another style or caller body.
2. **Normalization.** Read UTF-8, reject undecodable bytes, remove one UTF-8 BOM, normalize CRLF and CR to LF, preserve leading blank lines and every non-newline byte, and enforce exactly one terminal LF. `generation_prompt_template_snapshot_id` is SHA-256 over these normalized, pre-substitution canonical template bytes.
3. **Template and replacement domain.** Compilation reads the selected style pack's required `files.prompt_template`. The template must contain exactly one whole-line `{{NARRATIVE}}` injection token and no other `{{...}}` text-replacement marker of any casing; after removing that one token, any residual or unmatched `{{`, `}}`, `[[`, or `]]` delimiter fragment is invalid. The legacy `[[CANONICAL_NARRATIVE_BULLETS]]` and `[[STYLE_BASELINE]]` tokens are invalid for new canonical compilation and must not appear anywhere in the compiled body. The historical `EFFECTIVE_PAGE_SPECIFICATION` token is also invalid for new canonical compilation. Replace `{{NARRATIVE}}` with persisted canonical narrative bullets plus content material from the approved storyboard (role, assertion, audience takeaway, visual intent, content blocks and stable non-source `block_id` values); the narrative replacement and compiled body carry no case-insensitive structured source annotation such as `source =`, `[claim = ...]`, `data-source-id`, or an internal `SRC-` identifier followed by ASCII digits — source mapping stays in the coordinator/review layer only. The explicit default value is the three bullets headed `金字塔原理`, `精确表达`, and `层级执行`; default prose is never inferred at compile time. Every executable style-owned template is composed of the byte-exact hard shell plus exactly seven closed, typed Step-2 directives deterministically rendered from the same verified tokens; Role, Step 1, Step 3, compatibility, and final-output bytes are not style-customizable. `ppt-style-extract` statically materializes extracted colors, font stack, spacing, shape language, composition rules, and prohibited motifs into those seven `prompt.md` lines at pack-authoring time. A user brand/theme override that changes any of those values must be materialized and registry pointer-last registered under a new immutable style-pack ID before `theme.json` is finalized; `theme.selected_style_id` switches to that derived pack before initial generation. Runtime `StyleBaselineCompiler` output and `tokens.json.prompt_baseline` remain style-data resources, QA inputs, and snapshot-provenance inputs, never compiled-body injection or a second replacement domain. The `tokens.json` read here is the `schema_version: 2` style-pack asset; hand-authored token-string baselines are not a valid replacement source. The only runtime dynamic replacement domain is the single narrative injection.
4. **Byte identity.** The narrative replacement is normalized by rule 2 and must end in one LF. Compilation is non-recursive. Apart from the bytes injected at the single `{{NARRATIVE}}` token, every compiled-body byte is identical to the normalized style-owned prompt template. The template and resulting body must each contain exactly one ordered whole-line heading beginning with `# Role`, `## Workflow`, `### 步骤 1`, `### 步骤 2`, `### 步骤 3`, and `### 兼容约束`; fused, missing, duplicated, or reordered headings are invalid. CRLF and CR normalize to LF, while VT, FF, FS/GS/RS, NEL, U+2028, and U+2029 are never line boundaries and are rejected.
5. **Locked decisions and creative freedom.** Narrative logic is durable and locked: step 1 preserves the approved narrative (role, assertion, audience takeaway, visual intent, SCQA sequence) and the fact floor（事实底线）— exact numbers, units, periods, qualifiers (待确认, 待验收, etc.), and causal claims must stay true（不得改变数字、单位、期间、限定词、因果）. The generator may purify, rephrase, reorder, and expand only facts already materialized in the injected narrative; it cannot look up sources and must not add a new factual claim. Non-factual transition phrases are free. Step 2 follows the resolved template's embedded concrete style direction as a soft baseline: the generator freely chooses layout, hierarchy, card organization, density, palette usage, and decoration while keeping the whole deck consistent. Step 3 applies the fixed output contract verbatim. The generator does not re-choose narrative logic; it may optimize, rewrite, infer presentation emphasis, choose, and re-choose visual design within the baseline.
6. **SVG contract and source join.** The only generator response is one fenced XML block containing one complete Office-safe SVG. The canvas is `viewBox="0 0 1280 720"`; all visible content remains inside a 64px safe area; spacing follows a 24px rhythm. Rounded cards use `<path>` plus the SVG `A` arc command, never `rx` or `ry` on `<rect>`. Text uses explicit `<text>` elements and one simple, non-nested `<tspan>` per line. Each injected non-source `block_id` is echoed exactly once and only as the exact value of its semantic `<g data-block-id>`; it may not occur in visible `<text>`/`<tspan>`, node text/tail, or another attribute, and generator output must contain no source attribute or source ID. Before any candidate write or candidate hash, the coordinator joins those block IDs to the frozen storyboard's ordered source IDs, adds deterministic nested `<g data-source-id>` metadata, removes all `data-block-id` attributes, and canonically serializes the SVG. A missing, unknown, duplicate, leaked, or invalid mapping fails as `fact_source_mismatch` with zero candidate writes. The resulting SVG carries no source or citation annotation in visible text: no footer source line and no source-identifier reference may appear in any visible content. No `foreignObject`, script, remote resource, filter, or active content is allowed.
7. **Envelope.** Persisted bytes are a metadata prefix followed by exactly one separator `b"## Compiled Prompt\n\n"` and then the compiled body. The metadata prefix is `# <slide-id> 页面生成 Prompt`, a blank line, `## Snapshot metadata`, exactly nine metadata fields, and one blank line; it ends immediately before the separator. Metadata fields, in order, are `slide_id`, `storyboard_snapshot_id`, `theme_snapshot_id`, `applied_visual_revision_ids`, `prompt_snapshot_id`, `user_page_request`, `expected_output`, `workspace_output_path`, and `format`. The `format` field value is exactly `creative-brief-v1` for new canonical prompts and distinguishes them from legacy brief-compiled forms. The compiled body begins at byte 0 with `# Role` and ends with exactly one terminal LF. Preflight rejects a fused heading/body, a one-LF or three-LF separator, a repeated separator, a body not beginning `# Role`, and a body with zero or more than one terminal LF. The restriction to the two metadata-prefix headings applies only before the separator; canonical headings inside the body are required, not forbidden.
8. **Paths and dynamic-content preflight.** `workspace_output_path` is exactly `slides/<slide-id>.svg`. Before creating a durable transaction or dispatching a generator, reject the narrative replacement or a supplied body that contains: the old lean S01 form beginning `Role:` and containing `页面 ID:` plus custom `步骤 1/2/3` (or its English equivalent); `PROMPT_SCHEMA_VERSION`, `STYLE_ID`, `HARD_CONSTRAINT_IDS`, or untrusted-wording fence markers from historical redesign prompts; any unresolved or unmatched `{{`, `}}`, `[[`, or `]]` delimiter fragment; an injected ATX or Setext Markdown heading; any dynamic replacement marker other than the single template-owned whole-line `{{NARRATIVE}}`; a backtick or tilde JSON fence or a raw JSON object/array block; a Unix absolute path whose slash is at line start or follows a non-word/non-CJK boundary such as whitespace, colon, equals, or opening punctuation, Windows drive path, UNC path, protocol-relative URL, or any URI scheme including `ftp:` and `file:`; or instructions such as `Use the Read tool`, `invoke a tool`, read/load/open/fetch/consult an external file, and their Chinese equivalents including `参考外部文件`. General Unix-path detection applies to roots such as `/workspace`, `/Users`, `/data`, and arbitrary `/custom` segments rather than an enumerated root list. Semantic display-copy slashes such as `核心/支撑`, `收入/成本`, and `core/support`, where the slash follows a word or CJK character, are ordinary content and must not be classified as paths. Before creating a durable transaction or dispatching a generator, verify the narrative/material replacement: every number, unit, qualifier, and causal claim must match the approved storyboard, while source mapping is checked separately against the storyboard and no source annotation enters the replacement; a mismatch returns the slide to the storyboard owner as `storyboard_fact_mismatch`. For QA and snapshot provenance only, verify the selected style pack's `tokens.json.prompt_baseline` is readable and structurally valid before compiling a body. A missing or non-file tokens target maps to `style_assets_unavailable: style_asset_target_invalid`; unreadable or non-UTF-8 tokens map to `style_assets_unavailable: style_asset_unreadable`; malformed JSON or a missing/malformed `prompt_baseline` maps to `style_assets_unavailable: style_asset_malformed`; an unsupported tokens schema maps to `style_assets_unavailable: style_asset_schema_unsupported`. These failures create no body replacement. Also reject any body that cannot be decomposed byte-exactly into the resolved prompt template and the single validated `{{NARRATIVE}}` replacement domain.
9. **Body hash.** `compiled_prompt_sha256` is SHA-256 over only the compiled body bytes, starting at body byte 0 `# Role` and including its exactly one terminal LF. It excludes the metadata prefix, the exact `b"## Compiled Prompt\n\n"` separator, and every other envelope byte.
10. **Prompt snapshot payload.** `prompt_snapshot_id` is SHA-256 over canonical JSON bytes with no trailing LF. The payload contains: `applied_visual_revision_ids`, `compiled_prompt_sha256`, `format`, `generation_intent`, `generation_prompt_template_snapshot_id`, `generation_trigger_id`, `outline_snapshot_id`, `resolved_generation_prompt_template_path`, `selected_style_id`, `storyboard_snapshot_id`, `style_baseline_snapshot_id`, `style_kind`, `style_manifest_version`, and `theme_snapshot_id`. `style_baseline_snapshot_id` is SHA-256 over the normalized soft-baseline bytes that `StyleBaselineCompiler` produces deterministically from the active style pack's `tokens.json` `prompt_baseline` (palette roles, font stack, spacing rhythm, shape language, composition rules, prohibited motifs). The resolved template path is exactly `assets/styles/<style-id>/<files.prompt_template>`, derived from the selected style's manifest. Legacy visual-brief snapshot id and effective revision projection hash names, along with `style_prompt_snapshot_id` and `resolved_redesign_prompt_path`, are invalid for new canonical provenance.
11. Hash-capability fallback: when the host provides no deterministic SHA-256 capability, the orchestrator must not fabricate digests. Persist `generation_prompt_template_snapshot_id` and `compiled_prompt_sha256` as the literal `unhashed`, and persist `prompt_snapshot_id` / `transaction_id` as `unhashed:<token>`, where `<token>` is a run-scoped monotonic identifier (one plus the largest numeric suffix among existing `unhashed:` tokens recorded in this run's `run.json.interaction_history`, for example `gp-s03-3`) matching `[0-9a-z][0-9a-z-]*`; the candidate path then uses `slides/.candidates/<slide-id>-<token>.svg`. Resume verification degrades from digest comparison to re-deriving and comparing the nine metadata fields and payload keys; every other byte, provenance, preflight, operation, normalization, and stale-semantics rule above remains unchanged. Inventing a 64 hex digest without computing it is always a hard integrity violation.
12. **Transaction identity.** `transaction_id == prompt_snapshot_id`, including the `sha256:` prefix. A byte-identical canonical input repeats the same identity. Any change in the narrative replacement, style-baseline provenance bytes, resolved template bytes or path/hash, outline snapshot, operation owner, active revision IDs, or storyboard/theme provenance changes the prompt snapshot. `candidate_path` and other execution-only paths never enter the body or snapshot payload.
13. **Operation matrix.** `initial_generation`, `user_recompose`, and `deterministic_fallback` set `compile_full_prompt: true` and compile the canonical body before dispatch. `local_patch` sets `compile_full_prompt: false`, requires the current SVG, and does not compile a full generation prompt.
14. **Stale and conflict semantics.** Coherent resolved-template drift is ordinary stale and requires recompilation. `prompt_snapshot_conflict` is reserved for internally inconsistent provenance, stored body/hash mismatch, non-unique authoritative snapshots, invalid active-revision projection, conflicting operation owners, or envelope injection. A resolved template with invalid marker, heading, line-boundary, or required `data-block-id` instruction shape fails as `prompt_template_invalid`; narrative replacement or compiled-body injection violations fail as `prompt_preflight_invalid`. Prompt-baseline target, readability, JSON, structure, and schema failures are style-asset failures under rule 8, never generation-prompt reasons.
