# 叙事与故事板契约

## 目的

把已批准简报和证据台账转换为 `大纲.md` 与 `故事板.md`。输出必须构成完整文稿计划，能够在任何视觉设计开始前被冻结并交给独立审稿人。本阶段的批准与冲突处理遵循[用户交互与确认协议](interaction-protocol.md)。

## 结论先行的核心论点

先写出一个结论先行、能够回答受众核心问题并支持预期行动的核心论点。它必须具体到可以被反驳或限定；主题标签不等于核心论点。

使用金字塔逻辑：

1. 先给出统领全文的答案或决策；
2. 组织两到四个互不重叠的支持论点；
3. 把证据、影响、风险和行动放在对应论点下面；
4. 按决策逻辑而不是资料出现顺序排列各组内容。

证据不足以支持计划论点时，应缩小范围或加入限定。绝不能用布局隐藏薄弱论证。

## `大纲.md`

大纲记录：

- 核心论点与预期受众行动；
- 各章节结论及其与核心论点的关系；
- 重要 `claim_id` 与 `source_id`；
- 反方观点、风险、假设和未解决证据缺口；
- 开场背景、证明顺序、影响和收束；
- 建议页数；若与简报不同，应说明理由。

标题应表达结论，例如“人工交接是最大延误来源”，而不是“当前流程”这类主题标签。每个计划页面必须一页一个结论。章节页可以使用简洁的方向性结论，但仍须推动叙事。

## 大纲批准与故事板冲突

`guided` 写完大纲后，展示核心论点、预期受众行动、两到四个支撑论点、证明顺序、建议页数、被合并内容和仍存在的证据缺口，然后提出一个大纲批准问题。获得明确回答前保持 `stage: outline`，不得创建页面地图或故事板。`auto` 跳过可选批准并执行同等结构检查。

故事板不增加固定暂停。只有故事板冲突没有安全默认值时才询问，例如：页数上限与必需内容冲突、一页包含两个不可兼容结论、密度预算要求删除或拆页、无来源强结论仍被要求保留，或反方观点是否独立成页会改变核心叙事。每轮只处理一个最早的冲突；可通过保留限定、拆页或删除低优先级重复内容安全解决时直接处理并记录。

## 页面地图去重

编写故事板前，先创建包含页面 ID、叙事角色、结论、证据和转场的紧凑页面地图，并进行去重：

- 合并使用相同证据表达相同结论的页面；
- 拆分混合了无关结论的页面；
- 删除不会改变受众决策的重复背景；
- 解决相互矛盾的主张，或将其标记给文稿审查；
- 明确相邻页面的转场关系；
- 确认每个支持论点都对核心论点有贡献。

不得为了凑页数保留重复页，也不得为了压低页数把不同决策挤进一张超载页面。

## `故事板.md` 页面结构

每页创建一条记录，并在修订中保持 ID 稳定。每条记录包含：

- `slide_id`：`S01`、`S02` 等；
- `role`：cover、context、problem、evidence、comparison、process、architecture、implication、recommendation、close，或其他明确叙事角色；
- `assertion_title`：希望受众接受的单句结论；
- `audience_takeaway`：受众应该记住或执行的内容；
- `content_blocks`：按顺序组织的文案、主张、标签和图表／表格内容；
- `source_ids`：支持每个重要主张的来源 ID；只有不含事实的导航页才能使用空列表；
- `visual_intent`：视觉必须揭示的关系，而不是装饰物要求；
- `layout_family`：根据内容关系建议的语义布局家族；
- `density_budget`：low、medium 或 high，并明确文本、实体和比较数量上限；
- `previous_link`：上一页如何提出本页回答的问题；S01 使用 `START`；
- `next_link`：本页为下一页提出的问题或决策；最后一页使用 `END`。

每个内容块旁还要记录其支持的主张 ID。故事板中的文案必须已达到演示稿可用状态，不得保留占位文案、“添加图表”或未解决的创作指令。

## 密度与可读性

优先进行语义压缩，而不是缩小字号。

- 低密度：一条信息、一个视觉关系，最多两个支持细节；
- 中密度：一条信息和两到四个证据块；
- 高密度：确有必要的架构、比较、流程或数据视图，并具有明确层级。

内容超过密度预算时，应拆分为连续页面或删除低优先级内容，不能通过缩小字号解决。拆分后必须保留叙事链接和来源覆盖；字号不得低于视觉契约下限。

## 证据与风险检查

对每条故事板记录：

- 把数字、比较、因果、最高级、推动建议和时效性措辞映射到 `source_ids`；
- 保留 `研究.md` 中的限定条件；
- 在受众需要时展示重要反方观点或风险；
- 来源与主张不匹配时明确标记，不得悄然弱化引用；
- 图表必须说明指标、期间、单位和来源 ID。

没有来源 ID，就不能出现未加限定的重要事实主张。

## 文稿边界

完整文稿由冻结的 `简报.md`、`研究.md`、`来源.md`、`大纲.md` 和 `故事板.md` 组成。把工作流设置为 `manuscript_review`，然后执行独立审查契约。

不得直接根据故事板创建 `theme.json`、锚点样例或正式 SVG。只有顶层批准检查点已通过，并且 `run.json.manuscript_review.state` 持续为 `manuscript_approved` 时，视觉工作才能开始；此后顶层 `stage` 按视觉工作流继续推进。
