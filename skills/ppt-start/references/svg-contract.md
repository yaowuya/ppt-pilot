# Office-safe SVG 契约

## 文件与画布

每页都是独立 UTF-8 SVG 文件，并以稳定页面 ID 命名，例如 `slides/S03.svg`。根节点必须满足：

- `width="1280"`
- `height="720"`
- `viewBox="0 0 1280 720"`
- 标准 SVG namespace；
- 16:9 画布；所有非背景元素必须位于 `x=64..1216`、`y=64..656` 内，包括标题、页脚／来源和页码文字。判断文字位置时必须预留字形上升部与下降部，不能只把边界当作基线。

一页写入一个文件。不得嵌入演示文稿查看器、HTML 包装器或运行时脚本。

## 元素白名单

只允许以下元素名：

- `svg`
- `g`
- `rect`
- `circle`
- `ellipse`
- `line`
- `polyline`
- `polygon`
- `path`
- `text`
- `tspan`
- `title`
- `desc`

如果某个视觉必须使用其他元素，应使用以上子集重画，或选择更简单的布局。MVP 不得加入 `defs`、`use`、裁剪、遮罩、渐变、滤镜、图案或嵌入式位图。

## 禁止内容

页面不得包含：

- `foreignObject`、嵌入式 HTML 或仅浏览器可用的布局；
- `script`、JavaScript URL 或 `onclick` 等事件处理器（event handler）属性；
- 外部 DTD（external DTD）、自定义实体或 XML include；
- 远程资源（remote resource）、链接图像、远程字体或 CSS import；
- `<style>` 块或外部样式表依赖；
- animation 元素或动画属性；
- 指向用户目录、home、临时目录、Skill 或工作区的绝对路径（absolute path）；
- 任何需要 `url(...)` 的浏览器滤镜（browser filter）、模糊、阴影或效果；
- data URL 或 base64 载荷。

所有可见内容和矢量几何必须直接内联在 SVG 中。

## 属性与 ID

直接在元素上使用展示属性，例如 `fill`、`stroke`、`stroke-width`、`font-family`、`font-size`、`font-weight`、`text-anchor`，以及确有需要时的 opacity。属性值必须是静态值。

每个 `id` 都必须是文件内的唯一 ID（unique ID）。ID 使用页面级前缀，例如 `s03-title` 和 `s03-card-1`，不得依赖其他页面中的 ID。允许子集不需要 `href`；验证时如果发现它，其值只能是本地 `#fragment`，不能指向文件或 URL。

文字与属性必须执行 XML 转义（XML escaping）：`&` 写为 `&amp;`，`<` 写为 `&lt;`；引号位于相同属性定界符中时也必须转义。交付前必须把完整文件解析为 XML。

## 文字

文字保持为文字（text remains text）；标题、标签、正文和来源都不能转换为路径轮廓。

- 标题至少 40 px；
- 正文和数据标签至少 20 px；
- 脚注和来源至少 14 px；
- 使用 `theme.json` 中的系统字体栈；
- 每个 `text` 元素都显式声明 `font-size`；
- 使用 `data-role="title|body|footnote"` 标记文字角色。

每个可见行都使用 `<tspan>` 显式换行。每行设置 `x`，后续基线使用 `dy`。SVG／Office 没有可信的自动段落换行。文字无法放下时，应拆分内容或使用更简单布局，不能把字号缩到下限以下。

### 行宽估算（无渲染时的溢出判定）

宿主无法实际渲染时，生成前自查和 QA 几何检查必须使用同一公式逐行复核潜在溢出：

| 字符类别 | 估算宽度 |
|---|---|
| 全角字符（CJK 汉字、假名、全角标点） | `1.0 × font-size` |
| 大写字母与数字 | `0.6 × font-size` |
| 小写字母 | `0.52 × font-size` |
| 半角标点与空格 | `0.35 × font-size` |

- 行估算宽 = Σ(字符系数 × font-size)，必须 ≤ 该行所在可用区域宽 × 0.88（即至少 12% 余量）；
- 行距（基线到基线）至少 `1.4 × font-size`；多行文本块的总高不得超过所在区域高的 88%；
- 同一页所有文本行都要复核；估算超限属于硬失败风险，应先压缩文案、拆行或拆页，不得靠缩小字号通过；
- 实际渲染可用时，渲染检查结果优先于本估算；但估算仍应在写入候选前执行一次，以减少无效候选。

## 数据与来源映射

使用白名单中的矢量元素构建基本图表。坐标轴、柱、点、连接线和标签在页面尺度下必须清晰。重要数据主张通过相关分组或来源说明上的 `data-source-id="SRC-001"` 携带稳定来源 ID（source ID）。

每张图表必须说明指标、单位、期间和比较基准。不得推断缺失值、绘制超出资料期间的趋势，也不得用误导性基线编码差异。

## 可访问性与回退含义

根节点包含一个 `<title>`，内容为本页结论；还包含一个 `<desc>`，概括本页有意义的视觉关系。关键信息也必须以可读文字出现，不能只依赖颜色或形状。

装饰路径无需描述；承载含义的图标必须带相邻文字标签。禁止用 emoji 承载关键信息，因为字形渲染会变化。

## 验证

页面通过结构 QA 前必须：

1. 解析为 UTF-8 XML；
2. 核对精确画布与元素白名单；
3. 拒绝重复 ID、禁止元素、事件处理器、外部引用和机器路径；
4. 核对显式字号、`<tspan>` 换行，并确认所有非背景元素位于 64 px 安全区域；
5. 核对重要主张和图表是否暴露来源 ID；
6. 确认存在 `<title>` 与 `<desc>`；
7. 记录是否实际执行视觉渲染，以及具体渲染证据路径。

本契约面向可在浏览器中打开并插入受支持 PowerPoint 版本的静态 SVG。它不承诺所有 Office 版本或平台都能把 SVG 分解为完全可编辑的原生形状。
